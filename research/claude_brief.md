# 任務：建置瀏覽器遊戲「數位登山」(zh-TW)

在 /workspace/digital-hiking 建立一個純靜態網站（不需要 build；index.html + style.css + js/*.js + data/scenarios.json），可直接用任何靜態伺服器部署。UI 全部為繁體中文（台灣用語）。遊戲畫面中不要提到任何開發工具、AI、模型名稱。

## 參考網站 sansatemple.com 的類型（我們已分析）
這是一個「可走動的 Q 版療癒小互動場景」：玩家在一個場景中用「點地面走過去 / WASD / 方向鍵」移動；可拖曳看周圍；有數個可互動的動作按鈕（1/2/3 鍵、E/Space）；有輕鬆、安靜、溫暖的氛圍、可開關的環境音/音效、簡潔的底部操作說明、柔和色彩與卡片式 UI 面板。我們要做同類型的體驗，但主題是登山，且全部原創美術與程式（不得複製對方素材）。

## 遊戲概念
玩家操控一位 Q 版（chibi，大頭小身、圓臉、腮紅、大眼睛）登山客，沿著台灣山徑走一趟：登山口 → 森林 → 稜線 → 山頂 → 下山。路上會遇到「情境事件」，需在 3 個選項中選一個。選錯會增加「出事風險」（0–100 的明顯風險條，顏色由綠→黃→橙→紅，有表情/動畫變化，風險高時畫面變暗/起霧/天空變色、角色冒汗）。風險 ≥100 → 壞結局（呼叫救援／直升機救援畫面，教育性不嘲諷）。順利到達終點且風險低 → 好結局。結局後顯示「學習總結」：列出本趟每個情境、你選的、正確答案、為什麼（why）。有「再玩一次」按鈕，每次隨機抽題與隨機順序（選項順序也要洗牌；每趟約 10–12 題，依 stage 分配：trailhead 2–3、forest 2–3、ridge 2–3、summit 1–2、descent 2–3；不重複；題庫不足某 stage 時從其他 stage 補）。
- 風險結局分級：完成後風險 <20「平安滿載的山神級登山客」、20–49「有驚無險」、50–79「驚險下山（提醒需加強）」；風險 ≥100 中途結束「求救啟動」；80–99 完成也算「險象環生」。
- 答對也有正向回饋（小花、+經驗/徽章、角色跳起來）。答錯顯示「出事風險 +N」並搖晃畫面，但仍要在同一張卡片上立刻顯示解說。選完後點「繼續前進」。
- localStorage 記錄最佳（最低風險）結局與遊玩次數；已看過/答對的題目在下次優先抽到沒答過的題。
- 頁尾小字：「本遊戲為登山安全教育參考，實際行程請以官方公告與專業課程為準。山中緊急求救請撥 112（手機無訊號也可嘗試）或 119。」

## 資料檔
data/scenarios.json（先用現有的 3 題範例開發，之後會被置換為 50 題左右完整題庫；schema 如下，請勿改 schema）：
[{"id","category","stage":"trailhead|forest|ridge|summit|descent","title","situation","options":[3 strings],"answer":index,"risk":[3 ints 加到風險],"why","sources":[...]}]
用 fetch 載入。載入失敗要顯示友善錯誤。為了從 file:// 也能測，若 fetch 失敗可退回內嵌備援（可選）。

## 操作與畫面
- 使用 Canvas 2D 繪製（或 DOM+SVG 皆可），RWD 全螢幕、手機直式/橫式皆可玩。2.5D 俯視/側視皆可，建議：橫向捲動的山徑，路徑有一定寬度可上下走動（自由行走感），多層視差背景（遠山、雲、樹林、稜線、山頂雲海、下山的夕陽）；各 stage 有不同背景配色與裝飾（登山口：牌樓/告示牌/停車場小屋；森林：杉木/蕨類/蝴蝶/小溪；稜線：箭竹草坡/強風草/岩石/遠方雲海；山頂：三角點/石碑/雲海日出；下山：暖色黃昏、燈籠感）。
- 路徑上有「事件點」：可愛的「？」氣泡路標/小石碑/小動物。玩家走近會自動觸發（並有靠近提示），也可按 E/Space/點按鈕觸發。階段之間有牌子（例如「海拔 2,000m」「森林步道」）與進度條（頂部顯示 路線進度與 海拔）。
- 控制：鍵盤 方向鍵/WASD 移動；點擊/觸控地面走到該處；手機畫面左下角虛擬搖桿（或方向鈕），右下角「互動」按鈕。要支援 pointer events。音效開關按鈕（WebAudio 合成簡單可愛的音效：腳步、答對叮、答錯咚、背景風聲/鳥叫可選，預設靜音需使用者點開啟）。
- 角色：用 SVG/Canvas 程式繪製原創 Q 版登山客（帽子、背包、登山杖、腮紅、大眼），有走路擺動/彈跳、面向左右、休息呼吸動畫；風險高時冒汗、表情變擔心。NPC：Q 版黑熊、山羌、藍腹鷴、獼猴、蝴蝶、其他登山客（偶爾出現）等簡單裝飾。整體色彩柔和粉嫩但仍要有山的感覺（嫩綠、天空藍、米白、暖橘）。
- 事件卡片：底部或中央浮出可愛卡片，顯示分類標籤、標題、情境文字、3 個大按鈕選項（手機好按，≥48px），答後顯示對錯與解說（why）和「風險 +N」。字體用系統繁中字體（'Noto Sans TC','PingFang TC','Microsoft JhengHei',sans-serif），字級可讀。
- 開始畫面：標題「數位登山」、副標、角色與山景動畫、「開始登山」「操作說明」「查看成就/最佳紀錄」。「操作說明」彈窗。
- 結局畫面：好/普通/壞三類插圖（Canvas/SVG 繪製）、風險值、學習總結可捲動清單、再玩一次、分享按鈕（navigator.share / 複製文字，可選）。
- 效能與品質：requestAnimationFrame、處理 devicePixelRatio、視窗 resize、頁籤切換暫停。不要有 console error。無需外部 CDN 或圖片資源（全部程式繪製），字體用系統字體。
- 提供除錯/測試鉤子：window.__game = { state, startGame(), teleportToNextEvent(), triggerNextEvent(), answer(i), skipToEnding() } 方便自動化測試；以及 URL 參數 ?seed=123 固定隨機。
- 另外請寫 README.md（簡短）。

完成後自行用 Playwright（python3 已安裝 playwright，chromium 已有，可用 headless）跑一次煙霧測試：開啟 index.html（用 python3 -m http.server），走動、觸發事件、選答、確認風險變化、到結局；把截圖存到 screenshots/（start.png, walking-forest.png, scenario.png, ending-good.png, ending-bad.png；含手機尺寸 390x844 的 mobile-*.png），並修好發現的錯誤。最後簡短回報完成了什麼與已知問題。
