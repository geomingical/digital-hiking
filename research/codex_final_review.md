# 數位登山：最終 UI／美術審核

已逐張開啟 `screenshots/final/` 的 26 張 PNG，涵蓋桌機與手機全部提供狀態。以下以實際畫面為判斷依據，並核對 `style.css`、`js/gear-art.js` 的相關元素。僅提供修正建議，沒有修改產品檔案。

尺寸依使用者提供的 CSS 視窗理解；手機 PNG 為 780×1688，以下字級與間距都指 CSS px，不把雙倍像素當成實際字級。另 `d-08-walking-ridge.png` 實際為 1280×720，不能拿它與其餘桌機圖直接比較元件大小。

參考網站 [sansatemple.com](https://sansatemple.com/) 本次僅取得需 JavaScript 的入口文字，未能取得可供目視比較的遊戲畫面。風格標準採用題目指定的「溫暖配色、圓潤 Q 版、精緻 UI」，不宣稱已完成與該站的逐項視覺比對。截圖無法證明點擊、捲動、焦點及動畫是否正常；以下會區分可見問題與需實機驗收的風險。

目前最好的部分是角色的大頭比例、圓臉、腮紅與柔和山景，已經有親切的遊戲感。主要落差在資訊密度與狀態表達：桌機準備流程像密集清單，手機換裝又把太多高度留給摘要；A／C 換裝沒有足夠的視覺回饋。

P0 是會讓關鍵安全訊息不完整、或失去題目脈絡的問題。P1 是影響理解與主要操作的問題。P2 是美術與細節打磨。各級內按建議執行順序排列。

## P2：讓畫面更像完成的溫暖 Q 版遊戲

13. **選山插圖過度重複，辨識全靠山名。**

    圖片：`d-02-mountain.png`、`d-02c-ack.png`、三張手機 02，以及兩張 03。

    多座高山使用近似三角雪峰，草坡山也高度相似。大面積卡片因此仍像資料目錄。

    修改：延用現有 canvas 扁平畫風，為山岳 banner 增加各自輪廓與環境特徵，例如草坡、森林、裸岩與稜線。季節用少量雲、雨與植被色提示，不增加寫實照片。高山不要全年一律用雪帽代表。

14. **預覽角色可愛，但裝備遮住表情，且與場景角色的視覺份量不同。**

    圖片：`d-01-start.png`、`m-01-start.png`、三組 05、兩張 08。

    預設角色的大眼與腮紅很清楚；配齊後大墨鏡遮住眼睛，胸前手機、背帶、頭燈集中成一團。預覽的大頭感也比走路角色更強，連續體驗的比例稍有落差。

    修改：共用頭身比例、手腳寬度與臉部位置參數。讓墨鏡保留眼睛亮點或少量透光，維持裝備可信的形狀。胸前裝置略側移、縮小背帶對比，帽徽與腮紅沿用同一套尺寸。可增加眨眼或輕微站姿呼吸，但不靠動畫掩蓋靜態辨識問題。

15. **背包物品盤像圖示集合，欠缺名稱與分組。**

    圖片：A／C 的桌機與手機 05、`d-06-gearcheck.png`。

    急救包與頭燈可認，部分圓環、色塊、信封狀圖示則難知道實物。桌機檢查頁的圖示更小，難以核對帶了什麼。

    修改：`drawTray()` 依導航照明、補給、緊急備援分組，固定同一順序與格距。canvas 旁加 DOM 文字清單或點擊詳情，手機不能只依賴 hover。空背包狀態縮小留白，增加「前往背包挑裝備」按鈕；不要讓半個預覽區只留一句空狀態。

16. **手機季節頁下半留白過多，換裝頁卻擁擠。**

    手機季節資訊卡結束後到下一步之間有大段空白；換裝則把摘要、分頁與選項緊密堆在一起。桌機季節頁的左右分欄與空間較平衡，可保留。

## 修完後的驗收順序

1. 在 390×844 驗收完整安全文字與保命題卡的三種作答狀態，確認最後一行可讀、所有選項可回看。
2. 並排比較 A／B／C，不依賴選單文字也能分辨外觀；再確認長褲、鞋型與名稱一致。
